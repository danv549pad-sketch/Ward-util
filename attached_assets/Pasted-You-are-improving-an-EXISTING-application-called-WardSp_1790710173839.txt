You are improving an EXISTING application called WardSpace.

Do NOT rebuild the project from scratch.

First inspect the current codebase, routes, components, database, API endpoints and styling. Preserve working functionality wherever possible, then improve the product according to the specification below.

The goal of this iteration is to make WardSpace feel less like a generic prototype and more like a credible, simple, useful digital companion for everyday life on an inpatient mental health ward.

The product should remain explicitly NON-CLINICAL.

The core product proposition is:

WardSpace helps people know what’s happening, find something to do, get everyday things sorted and have a say in the ward.

Do not add clinical monitoring, diagnosis, medication advice, risk scoring or therapeutic decision-making.

⸻

1. PRODUCT DIRECTION

WardSpace should become the:

DIGITAL FRONT DOOR TO THE WARD

The application should answer four primary questions quickly:

1. What’s happening?
2. What can I do?
3. Can I request something?
4. Where can I find information?

Almost everything should be reachable within two taps.

Reduce complexity.

Do not add unnecessary features.

Focus on:

* clarity
* speed
* accessibility
* usefulness
* engagement
* simple staff administration

24. SECURITY — IMPORTANT NOW THAT THE APP MAY BE PUBLIC

The original demo PIN may have been:

2468

Do NOT continue relying on an exposed/default hard-coded PIN.

Improve prototype staff security.

Requirements:

* staff authentication validated server-side
* password/PIN must NOT be stored in client-side JavaScript
* use environment variable for staff credential
* add server-side staff session
* use secure cookies where possible
* protect ALL staff/admin API endpoints
* hiding a button is NOT authorization
* add basic login rate limiting
* add logout
* expire staff session after reasonable inactivity
* prevent patient endpoints from calling staff mutation routes

Create environment variable such as:

Do not hard-code its value.

If no environment variable exists in development, clearly explain setup in README rather than silently using 2468 in production.
