Improve the EXISTING WardSpace application. Do not rebuild it.

The next priority is to properly distinguish between PERSONAL DEVICE usage and SHARED WARD DEVICE usage.

This is important because WardSpace may be accessed both by:

1. A patient using their own phone after scanning the WardSpace QR code.
2. Multiple patients using the same communal ward tablet/touchscreen.

The current architecture must not assume that one browser always represents one person.

DEVICE MODE

Add two operating modes:

PERSONAL DEVICE

Intended for someone’s own phone/tablet.

Features available:

* Today
* Discover
* Ask / Suggest
* My Stuff
* activity interest
* suggestions
* requests

My Stuff may use localStorage as currently implemented.

Display a subtle indicator:

Personal device

⸻

SHARED DEVICE

Intended for communal ward tablets/touchscreens used by multiple people.

Display a persistent but unobtrusive indicator:

Shared device

My Stuff must NOT expose information saved by a previous user.

Never display persistent personal notes belonging to a previous shared-device session.

SHARED SESSION

When someone enters My Stuff on a shared device, create a temporary local session.

Display:

This is a shared device

Anything you add to My Stuff during this session will be removed when you finish.

Button:

Start My Session

During the session allow:

* Things I want to ask
* Things I need to sort
* Things I want to do

Store these only in temporary session storage, NOT persistent localStorage.

Provide a persistent button:

Finish & Clear My Session

When selected:

1. Ask for simple confirmation.
2. Delete all temporary personal session data.
3. Return to Today.
4. Display:

Your session has been cleared.

Automatically clear the shared My Stuff session after a configurable inactivity period, for example 10 minutes.

Do not auto-clear while the user is actively interacting with the app.

PRIVACY

On shared devices clearly explain:

Personal notes on this shared device are temporary and will be removed when you finish your session.

Never expose notes from a previous shared session.

Do not send My Stuff data to the server.

DEVICE MODE CONFIGURATION

Allow device mode to be configured intentionally.

For example:

/?mode=shared

or an installation/configuration option.

Store the selected DEVICE MODE locally.

Do not allow ordinary navigation to accidentally switch modes.

Staff should be able to configure a communal tablet as Shared Device.

The noticeboard remains inherently shared/read-only.

SHARED DEVICE HOME SCREEN

Shared-device mode should prioritise:

* what’s happening now
* what’s happening next
* activities
* requests
* Ward Guide
* suggestions
* Daily Challenge

Do not make private/personal functionality visually dominant.

ACTIVITY INTEREST

Review the existing anonymous-session implementation.

Do not assume a shared browser represents one patient.

For PERSONAL MODE:

Current browser/session-based interest behaviour may remain.

For SHARED MODE:

Create a separate interaction model suitable for multiple anonymous users.

At minimum, prevent one person’s interaction from appearing as though every subsequent user on the communal device has already selected “I’m in”.

A shared-device user selecting:

I’m in

should receive:

Thanks — interest recorded

The UI should then return to its neutral state after a reasonable short period or after the shared session ends.

Document that anonymous shared-device counts are indicative engagement signals rather than authenticated attendance records.

Do not attempt biometric, fingerprinting or identity tracking.

REQUESTS ON SHARED DEVICES

After a practical request is submitted on a shared device:

* clear the request form immediately
* do not retain the request text in browser history/local state
* return to a neutral confirmation state

Display:

Request sent

and:

WardSpace requests are not monitored for urgent help. If you need someone now, please speak directly to a member of staff.

After a short period, return to the default Ask / Suggest screen.

PRIVACY RESET

Add a global action on shared devices:

Finish

or:

Clear my session

This should:

* clear temporary My Stuff data
* clear unsent forms
* reset temporary activity UI state
* reset temporary suggestion UI state
* return to Today

Make this easy to find.

INACTIVITY

For SHARED MODE only:

After approximately 10 minutes of inactivity:

* clear temporary user/session UI data
* return to Today

Do NOT delete shared server-side public content.

Do NOT delete successfully submitted requests or suggestions from the database.

This reset concerns only data remaining in the browser.

STAFF SETTINGS

Add a basic Staff setting showing:

Device configuration

Personal / Shared

For a shared physical ward tablet, allow staff to configure Shared mode.

Do not store clinical or patient identity information as part of this feature.

TESTING

Test the following scenario carefully:

Patient A:

1. Opens shared tablet.
2. Starts My Stuff session.
3. Adds “Ask about housing”.
4. Finishes session.

Patient B:

1. Uses the same browser.
2. Opens My Stuff.
3. Must NOT see “Ask about housing”.

Then test inactivity clearing.

Test request forms do not retain previous user’s text.

Test activity interest does not expose the previous shared user’s selected state.

Test Personal Mode still keeps the user’s own My Stuff information as before.

Do not break:

* Today
* Discover
* Ask / Suggest
* Daily Challenge
* Staff Dashboard
* Noticeboard
* existing SQLite content
* existing protected staff routes

Implement the change and provide a completion report describing exactly how shared/private browser state is separated.
